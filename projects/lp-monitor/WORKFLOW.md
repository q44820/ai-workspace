# 工作流程｜LP区间与钱包监控

## 目的与数据流

低频只读钱包核对 → 增删有效NFT仓位 → 更新本地清单 → 高频公开价格检查 → 低频区间提醒。

## 修改前

1. 阅读仓库AGENTS.md、PROJECTS.md、此项目STATUS.md和当前任务。
2. 获取唯一任务编号与写入负责人；从最新main创建独立分支。
3. 先复现问题，区分代码缺陷、数据缺失与外部接口变化。
4. 不修改生产服务、定时任务、真实账户或外部状态，除非另有明确授权。

## 开发与验收

- 先用明确标注的测试样本验证，不能把模拟输出当实时行情。
- 运行上述测试与仓库级核验；如有联网验收只读并记录时间及限制。
- 检查新增数据/通知/配置副作用，不能因测试发送真实提醒。
- 更新STATUS、CHANGELOG和任务记录，附测试结果、未覆盖条件与回退方法。
- 通过PR交给其他AI/用户审阅，再合并；不是自动部署。

## 已知限制

仅链上读取，无签名交易；--apply/看门狗会改本地监控配置，通知会对外发送；生产钱包、推送参数不在仓库；并非所有链通用。

## 下一个候选任务

提供各链独立配置契约；补充分频、空仓静默与重复提醒测试。

## 回退

通过Git提交回退本仓库代码，不自行重启或修改旧服务。运行状态需单独核验。
