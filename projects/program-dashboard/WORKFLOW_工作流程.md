# 工作流程

1. 仅登记GitHub已有项目：先补`catalog.json`的功能/用途/代码链接；一个项目中的独立程序按真实脚本分别列卡片，不能因共享项目目录就隐藏BNCB/BNB等具体功能。未进入GitHub的旧任务不登记，且不因此停止或删除它们。只登记必要信息，不写账户、真实主机或连接配置。
2. 增加服务时显式加入`SERVICE_MAP`白名单，不枚举/回传完整进程命令行；本机状态同样只允许白名单字段。
3. 单元测试确保未知/失败不是停止，过期本机数据不是实时状态，访问码错误不可读、写方法405。
4. 本地验收后单独授权部署本看板组件，回读精确线上文件并用外网浏览器验收搜索/筛选/手机布局。
5. 状态异常只展示，不自动恢复、重启、改交易模式或取消订单。
6. 临时隧道URL重启可能变化；固定域名/正式认证需单独配置授权。
7. 若未来替换本机SSH认证，使用独立最小权限只上传账号/密钥；当前私密上传配置不进入Git。
8. 有已部署网页时，将经核实的HTTP/HTTPS入口放服务器私密`runtime/web_links.json`，键为catalog项目ID；不得携带用户口令。程序名称显示新标签页链接；未知入口不编造、未授权不得开放新的服务端口。
