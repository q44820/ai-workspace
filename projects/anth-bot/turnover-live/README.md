# 小额真实刷量：用户自行启动

与 `paper.html` 模拟和原 `anth-bot` 实盘套利服务分离。部署/打开页面/查询状态不会初始化签名器或下单。只有用户在带认证的日本网页勾选风险确认并点击启动后，后端才进入预检。默认停止，重启不恢复交易。

## 本次固定上限

- 两所 IO:ANTH / Lighter ANTHROPIC 开仓＋平仓 **合计1000U** 达到后不再开仓；收尾可超量，不能为了卡数字留仓。
- 每轮 **双边开仓合计≤50U**（每腿约25U，按精度向下取整并留30bp价格余量）；不能将50U当每腿额度。
- 已实现净额＋实际资金费＋按盘口估计的未平损益及退出费达到 **−3U** 停止开仓并尝试收尾。不是亏损担保，未知回报/断流可能无法收尾。
- 页面与服务端均只允许调低上限。一次试验会话不可通过重复启动重置预算，不提供清账重刷按钮。
- 下单前检查原套利服务：active/unknown 一律拦截。不停止它，不修改其账户杠杆或仓位。
- 仅使用服务器已有 SDK 和私有环境授权，不把密钥、API凭据、账户编号、私密入口发送到网页或公开仓库。

## 执行规则与模拟的差异

60秒实际行情预热、IO被动开仓、Lighter仅对冲已确认成交量、优先保本退出，持仓60秒后允许12bp限损挂单，10分钟或30bp止损尝试吃单。计价、收益、成交额均为U。

**不是与模拟逐行相同的执行器**：实盘不等待虚构成交，所有数量由交易所订单终态＋成交ID确认，未知不重发；不故意等500ms再对冲。IO挂单采用短时有效窗口、15秒后撤回并确认终态，以减少无人知晓的活动订单；会影响排队效率，不宣称保留模拟队列效果。实际真实费用取成交账单，实际资金费查询失败停止新开仓。费用估值筛选沿用模拟的保守费率，但最终损益不把该估值当实际手续费。

**风险限制**：API超时可能留下未知活动订单/单腿仓，状态进入`needs_review`而不是假报停止空仓；禁止盲目补单。可确认且归属本会话的残余仓才使用reduce-only收尾。原套利重新启动/出现外部交易时冻结避免误平，不承诺自动救回。收尾滑点、部分成交、资金费更新延迟可能超过额度/亏损线。

## 网页与鉴权

日本整合站的认证路径下 `anth-turnover-live/`。浏览器只与同源API通信，本地控制面只监听127.0.0.1:8911，使用私有服务令牌＋页面CSRF，写请求检查Origin。原站其余路径保持只读；无CORS，无第三方脚本，无公开账户/密钥。注意：持有整合站能力链接的人具有访问权限，勿分享。

API服务启动不等于开始交易。新systemd服务只运行HTTP控制面，不自动启用任何交易会话。原套利服务/代码/.env保持不变；该程序使用同一账户所以不能并发。要做到无冲突并发，需要用户独立交易子账户，而不是仅修改订单编号。

## 故障诊断与读取重试

控制面显示后端构建指纹，部署必须读回指纹匹配，不能只比对磁盘文件。行情、持仓、资金费的暂时性超时/429/5xx最多重试三次，仅针对读取；提交、撤单结果及未知订单绝不据此重发。资金费每30秒刷新一次，读取失败仍阻止新开仓。异常只保存调用阶段、类型、HTTP状态和代码行号，不保存请求/响应正文、地址、授权或密钥。

已对服务器所装Lighter SDK资金费参数 `market_ids` / `start_timestamp` 建立严格签名回归。只读认证显式指定已配置API索引和600秒有效期；下单仍使用SDK自身的nonce/key管理，避免绕过nonce互斥。浅盘口跳过报价、首次冷却字段为空按未平过仓处理，对冲数量无法精确表示时拒绝提交；部分成交必须先确认撤单终态并核实实际成交账单。上述分支均有离线回归，不代表真实签名、权限或成交链路已得到实盘验证。

故障会话如未发送订单，可在逐项核实两所仓位/挂单为零、订单日志/成交均空后归档，保留原始状态并回到待用户手动启动；不得清除有交易历史或未知订单的预算记录。

当Lighter逐笔成交省略费用或盈亏字段时，不把空值当零：读取官方免鉴权 `aggregatedTrades`，逐项核对账户、订单、市场、方向、角色、笔数、首末成交ID、数量和金额后才记账。费用必须明确为USDC；开仓聚合PnL为空按官方“未减仓”语义记0，减仓PnL为空仍冻结。已有未知订单会话不得因代码修复自动解冻或清账。

## 手动平仓后继续测试

只有独立核对真实空仓/无挂单、补齐官方开平账单并备份旧状态后，才设置 `resumeReady`。网页显示“继续原会话”，仍须用户勾选并点击；刷新、GET和部署不会启动交易。继续沿用原会话ID、开始时间、累计成交、费用和1000/50/3限制，不能扩大原限额或清零亏损预算。资金费未核实显示未知，继续后先查询完整原会话资金费，未知时不开仓。旧冻结/未知订单不能仅凭前端继续参数绕过。

## 账单延迟与异步启动

启动接口先返回 HTTP 202，由状态轮询显示 `startPending`；预检期间禁止第二次启动，用户停止可取消后续交易。网页对非JSON响应明确提示请求可能已生效，并立即只读核实，绝不自动重发。

已确认订单的聚合账单暂时为空时，最多在45秒确认窗口内重查订单/账单；仅重试暂时性读取故障，不重复提交或撤单。账户、费用资产、订单身份等不匹配仍立即阻断，45秒后仍不明仍冻结。`test_full_flow.py` 从HTTP启动经过预热、多轮开平、延迟账单、达标收尾到重启账本核对；数据全部为明确标注的离线fixture，不冒充真实运行证明。
